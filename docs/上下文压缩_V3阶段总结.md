## 1.5 服务架构（重要）
- 2D/3D 构建在**独立常驻子进程**中执行（各一个 worker），主进程只做路由：
  - 3D 构建期间页面/2D 请求不阻塞（OCC 布尔会占住 GIL，原先会导致服务器整体假死）；
  - 看门狗：构建超过 BUILD_TIMEOUT_S=60s → 杀子进程并重启，返回"构建超时，请重试"。
- 服务器本身不再带热重载（子进程架构后每次改动需重启服务器）。

## 3. 已实现
- P0 自由多边形/正多边形/三角形；直线、凸弧、凹弧；多解按钮；快速参数粘贴。
- 正多边形模式也支持多解：等价自由多边形可能有 2 个解（如正五/六边形），
  解按钮自动出现，freeSolution 路由到对应解（解1 = 标准正多边形）。
- 卡扣：直线卡扣锚点 = P0 边中点在 P1 直线段上的垂足（2D 红点同规则）；
  凸/凹弧端面绕 e_in/e_out 旋转；凹弧安装弦平面定位；凹弧与卡扣间 1mm 月牙填充。
  2D 弧边红点 = P0 弧中点在 P1 弧上的垂足（3D 弧边卡扣保持弦平面定位）。
- P1 顶点圆角：内角 [15°,180°) 做切线圆角，半径 P1_CORNER_R = 0.05mm；
  [180°,345°] 凹角不圆角；<15° 或 >345° 跳过 + 红字提示"当前图形某内角小于/大于…°，暂不支持"。
- 包边（沿 P1 轮廓、两相邻卡扣之间，按顶点内角分段）：
  - 凸角 [15°,180°)：整段扫掠，跟随圆角弧；
  - 180° 平滑过渡（共线/相切）：整段通过；
  - 凹角 (180°,345°)：拆两段——段A：前卡扣前向交点→顶点；段B：顶点→后卡扣后向交点，
    各自独立扫掠（整段 frenet 穿过尖锐凹角会法线翻转 180°）；
  - <15° / >345°：不铺（红字提示在圆角阶段给出）；
  - 卡扣端面区间退化（交点缺失/同边）→ 只跳过缺失的那一段并记录可粘贴用例；
  - 包边两端与卡扣留空 WRAP_END_GAP = 0.02mm（避免端帽与卡扣端面共面：
    共面时 glue=False 并集 invalid、glue=True 吞实体）。

## 5. 本次实现的关键技术决策（自行假设并记录）
1. 凹角包边拆两段而不是整段扫掠（整段会法线翻转）。
2. 凹角段A 在顶点前 0.05mm 停止（断开共边接触），并加一段独立扫掠的
   "延长段"（沿边 k 走 2mm）与段B 同路径重叠，保证凹角处连续。
3. 包边"外侧"方向按外边环绕向计算（面法向 Z>0 → 切线右法线），
   不用"远离面心"判定（凹多边形靠近凹角的边会把包边铺到板内侧）。
4. 卡扣端面交点检测加 0.02mm 容差，识别"交点恰好落在路径顶点"的情况。
5. 端点区间退化时按"段"粒度处理：只放弃缺交点的那一段，其余照铺。
6. clean()/fix() 会就地修改 TopoDS，包边（带相切边界）后再调用会破坏实体，
   因此只在卡扣融合后、包边之前调用一次。
7. 包边扫掠采用混合策略（2026-08-28 修正）：
   - 默认整段 frenet 扫掠（凸角圆弧连续无缝），失败回退逐段扫掠；
   - 弧扫掠实体在部分组合下会被 OCC 布尔并静默丢弃（如 80/R80 凹弧段的
     段B：与段A 互相排斥，任何融合顺序都有一块被吞）——融合不完整时对
     该角整组做**折线化重试**（圆弧拆成 ≤1mm 弦，弦高差≈0.002mm，
     全部直线扫掠后布尔稳定）；
   - 不要全局折线化+纯逐段：凸角圆弧会因逐段端帽楔形缺口出现可见空缺。
